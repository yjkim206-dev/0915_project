# 게시글 첨부

게시글 작성·수정 폼에서 이미지·영상·문서를 선택하면 Supabase Storage로 직접 업로드합니다. 파일 본문은 서버 디스크·Vercel·DB에 중복 저장하지 않습니다. DB에는 파일명·유형·크기·소유자·게시글 연결 정보만 기록합니다.

- 비공개 버킷: `post-attachments`
- 경로: `YYYY-MM-DD/검증된 회원 UUID/서버가 생성한 파일 UUID.확장자` (한국 날짜)
- 게시글당 최대 10개, 합계 200MiB. 이미지 10MiB, 영상 50MiB, 문서 20MiB.
- JPEG/PNG/WEBP/GIF/AVIF, MP4/WEBM/MOV, PDF/TXT/ZIP/DOCX/XLSX/PPTX 지원.
- 실제 Storage 메타데이터의 크기·MIME와 헤더 바이트를 확인한 뒤 게시글에 연결합니다. HTML/SVG/실행파일은 허용하지 않습니다. 헤더 검사는 전체 파일의 악성코드 검사를 대체하지 않습니다.
- 게시글과 첨부 목록은 DB 트랜잭션으로 저장합니다. 다른 회원의 첨부나 미완료 파일은 연결할 수 없습니다. 수정 저장이 완료되기 전에는 기존 첨부를 삭제하지 않습니다.
- 공개 글은 누구나 첨부를 볼 수 있고 숨긴 글은 작성자에게만 링크를 발급합니다. 다운로드 링크는 5분간 유효하며 만료되면 '첨부 링크 새로고침'을 누릅니다. 이미 발급한 링크는 최대 5분 동안 유효할 수 있습니다.
- 글·계정 삭제나 첨부 제거 시 삭제 큐에 넣고 5분 간격으로 Storage API로 정리합니다. 작성 취소 시 임시 파일을 제거하고, 브라우저 종료 등으로 남은 임시 파일은 24시간 후 정리합니다. 서명 업로드 토큰 유효 기간 중 늦게 올라온 파일도 재점검합니다.
- 새 첨부 파일은 서비스 백업에 함께 포함됩니다. 백업 버킷은 재백업하지 않습니다.

배포 시 `node backend/supabase/configure-attachments.mjs`로 DB 025·026, 비공개 버킷, 정리 스케줄을 등록한 뒤 Edge Function `api`와 프론트를 배포합니다.
