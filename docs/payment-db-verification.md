# 결제·크레딧 실제 DB 검증

- 검증 시각: 2026-10-19 13:36 KST
- 대상: `ymprvqsfpwvoutwozwvn` Supabase 프로젝트의 배포된 `api` Edge Function 및 실제 PostgreSQL 테이블
- 실행: `node backend/test/payment-integration.mjs --allow-remote-fixtures`
- 결과: 기능 검증 16개 시나리오 통과, 임시 데이터 삭제 및 DB 정리 확인 통과

API 응답만 확인하지 않고 서비스 역할로 `credit_wallets`, `credit_transactions`, `payment_orders`를 직접 조회해 대조했다.
기존 유저와 분리된 임시 일반 유저 2명과 임시 관리자 1명을 사용했다.

| 항목 | 확인한 실제 DB 결과 |
| --- | --- |
| 비로그인 권한 차단 | 관리자 조회·지급 요청 401, 지갑 0P·원장 0건 유지 |
| 일반 유저 권한 차단 | 관리자 API와 직접 지급 RPC 403, actorId 위조로 우회 불가 |
| 직접 지갑 변경 차단 | 유저의 REST PATCH가 지갑 잔액을 변경하지 못함 |
| 관리자 지급 | 0P → 1,000P, `admin_grant` 원장에 관리자·사유·요청번호·변경 전후 잔액 일치 |
| 관리자 회수 | 1,000P → 800P, `admin_revoke` 원장에 -200P 및 관리자·변경 전후 잔액 일치 |
| 잔액 초과 회수 | 409, 잔액 800P·원장 2건 유지 |
| 같은 요청 재전송 | 1,000P 지급 재시도에도 잔액 1,000P·지급 원장 1건 유지 |
| 동시 중복 지급 | +25P 요청 2개를 동시에 보내도 1건만 적용, 잔액 825P |
| 동시 회수 | -600P 요청 2개 중 1건만 원장에 기록, 잔액 225P로 음수 방지 |
| 미결제 주문 취소 | `cancelled`, 취소 사유·시각이 DB와 API에서 일치. 재시도 시 최초 기록 유지 |
| 타 유저·승인 주문 보호 | 타 유저 취소 요청 404. 승인된 주문은 `paid` 유지 |
| 환불 예약 | 환불 대상 크레딧 예약 후 가용잔액 225P, 이를 초과한 관리자 회수 차단 |
| 환불 예약 해제 | 가용잔액 1,225P 복구, 예약 플래그 해제 |
| DB 환불 확정 | `refunded`, 취소 사유·시각·금액 저장, 환불 원장 1건, 재시도 중복 차감 없음 |
| 원장·지갑 대조 | 최종 크레딧 원장 합계와 실제 지갑 잔액 모두 225P |
| 조회 격리 | 직접 DB 조회 시 RLS가 본인 주문만 반환. 관리자 회원별 조회와 사용자 내역 일치 |

검증 종료 후 임시 Auth 계정 3개를 삭제하고 `users`, `profiles`, `admins`, `credit_wallets`,
`credit_transactions`, `payment_orders`, `subscriptions`에서 해당 계정의 행이 0건임을 직접 확인했다.

이 검증의 결제·환불 데이터는 격리된 테스트용 주문이다. 실제 Toss 승인·취소 API를 호출하거나
금액을 청구하지 않았다. 영수증은 저장된 URL의 반환과 개인정보·키 미노출을 검증했으며,
실제 Toss 영수증 발급·카드 취소 완료를 증명하는 테스트는 아니다.

## 운영 화면 추가 검증 (2026-10-19)

실제 운영 주소 `https://0915-project-ruby.vercel.app`에서 headless Edge로
로그인부터 로그아웃까지 검증했다. 테스트 토큰을 브라우저 저장소에 주입하는 대신
유저·관리자 로그인 폼에 임시 계정 정보를 입력해 실제 인증 흐름을 통과했다.

실행: `npx.cmd --yes --package=playwright -c "node backend/test/payment-browser.mjs --allow-remote-fixtures"`

결과: 브라우저 검증 15개 항목 통과, 임시 Auth 계정 2개 삭제 완료.

- 관리자 로그인 폼으로 운영 관리자 화면 진입 성공
- 일반 유저의 관리자 로그인 거절 및 관리자 토큰 미발급
- 유저 로그인 폼으로 정상 로그인
- 관리자 지급 버튼으로 300P 반영 및 감사 원장 표시
- 유저 프로필에 잔액 300P, 구매상품, 저장된 영수증 URL, 주문 상세 표시
- 모의 취소 복귀 URL에서 `cancelled`와 취소 사유·시각이 실제 DB에 저장
- 모의 실패 복귀 URL에서 `failed`와 실패 코드·사유·시각이 실제 DB에 저장
- 전체 결제내역의 취소·실패 필터에서 해당 DB 주문만 표시
- 모바일 관리자 회수 버튼으로 300P → 200P 반영
- 유저·관리자 로그아웃 후 인증정보 삭제 및 보호 페이지 접근 차단
- PC 프로필·관리자, 모바일 프로필·전체 결제내역·관리자 화면 가로 넘침 없음
- 브라우저 실행 오류 및 로컬 주소로 향하는 요청 없음

취소·실패 복귀는 합성한 테스트 파라미터로 검증했다. 실제 Toss 결제창에서
승인·취소를 실행한 검증과는 구분한다. 영수증 링크도 테스트 주문에 저장한
검증용 URL로 표시 여부만 확인했으며 실제 영수증 발급을 검증하지 않았다.
